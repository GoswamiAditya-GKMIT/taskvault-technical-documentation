    System Architecture

    TaskVault follows a layered backend architecture that separates responsibilities clearly and keeps business logic maintainable.

    Request Flow:

    Client
    → URL Router
    → DRF Views (Permissions & Auth)
    → Serializers (Validation)
    → Service Layer (Business Logic)
    → Models (Data Structure)
    → PostgreSQL Database

    Architectural Principles

    • API-First Design: All functionalities are exposed via RESTful endpoints.
    • Separation of Concerns: Logic is decoupled into Views, Services, and Models.
    • Multi-Tenancy: Data is logically isolated by organization_id.
    • Soft Deletion: Entities are marked as deleted rather than physically removed.
    • Immutable Audit Logs: Critical changes (task status, payments) are permanently recorded.

    Deep Dive: Tech Stack & Components

    1. Core Framework

    • Django 6.0: The backbone of the application, utilizing its ORM for database abstraction and signal system.
    • Django REST Framework (DRF): Powers the API layer with robust Serializers for validation and ViewSets for logic.
    • PostgreSQL (psycopg 3 driver): Primary relational database chosen for its reliability and JSONB support (used in Webhook payloads).

    2. Asynchronous & Background Processing

    • Celery: Distributed task queue handling long-running operations.
      • Tasks: sending emails (users.tasks), processing webhooks (subscriptions.tasks).
    • Celery Beat: Scheduler for periodic maintenance jobs.
      • Jobs: reconcile_pending_subscriptions (Hourly), hard_delete_unverified_users (Daily), clear_blacklisted_tokens (Daily).
    • Redis: In-memory data store acting as:
      • Message Broker: For Celery task queues.
      • Cache Backend: Using django-redis for caching API responses and sessions.

    3. Email Service

    • Brevo (formerly Sendinblue): Transactional email provider via SMTP relay.
      • Used for Invitation links, Password Resets, and Email Verification.

    4. Middleware

    • LoggingMiddleware (core.middleware): Custom middleware that intercepts every request/response loop to log metadata (User ID, Path, Status Code, Duration) to JSON logs for observability.

    4. Payments

    • Razorpay Integration: Handles all payment processing.
      • Uses Webhooks for real-time status updates (e.g., payment.captured, payment.failed).
      • Dedicated webhook_events table ensures idempotency.

    Modules Breakdown

    Module Description Key Components
    core Foundation layer. LoggingMiddleware, JSONFormatter, Custom Exceptions, IsSuperAdmin/IsTenantAdmin Permissions.
    users Identity & Access Management. User, Organization models. auth endpoints (/login, /verify-otp), RegisterAPIView.
    tasks Project Management domain. Task, Comment, TaskHistory models. TaskViewSet with complex filtering logic.
    subscriptions Billing & Revenue. Subscription, Payment, WebhookEvent. razorpay utilities, atomic transaction services.
