    Authentication & Security

    TaskVault uses JWT (JSON Web Token) for stateless, secure authentication. All protected endpoints require a valid access token in the header.

    Authentication Mechanism

    • Access Token: Short-lived (e.g., 2 hours). Used for API access.
    • Refresh Token: Long-lived (e.g., 7 days). Used to obtain new access tokens.
    • Header Format: Authorization: Bearer <your_access_token>

    Authentication Flows

    1. Registration & Verification

    1. Register: User POSTs to /api/v1/auth/tenant/<tenant_id>/register/ (or via invite link).
    2. Email Verification: System sends a verification link to the user's email.
    3. Verify: User clicks link -> POST /api/v1/auth/email-verification/verify/ with token.
    4. Constraint: Users cannot login until is_email_verified=True.

    2. Login with OTP (2FA)

    1. Login Request: POST /api/v1/auth/login/ with email/password.
    2. OTP Challenge: If valid, system sends an OTP to email and returns a temporary session hash (not yet a token).
    3. Verify OTP: POST /api/v1/auth/login/verify-otp/ with email, OTP, and session hash.
    4. Resend OTP: If expired, POST /api/v1/auth/login/resend-otp/.
    5. Success: Server returns access and refresh tokens.

    3. Password Management

    • Forgot Password: POST /api/v1/auth/forgot-password/ triggers an email with a reset link.
    • Reset Password: POST /api/v1/auth/reset-password/<token>/ allows setting a new password.
    • Change Password: Authenticated users use POST /api/v1/users/change-password/.

    4. Invitations

    • Tenant Admins generate invites via POST /api/v1/users/invite/.
    • New users register via POST /api/v1/auth/invite/<token>/register/.

    Token Management

    Refreshing Tokens

    When the access token expires, use the refresh token to get a new pair: POST /api/v1/auth/refresh/

    Logout (Blacklisting)

    To securely logout, the client must send the refresh token to be blacklisted: POST /api/v1/auth/logout/ Effect: The refresh token is invalidated immediately.

    Security Features

    • OTP Rate Limiting: Prevents brute-force on 2FA.
    • Token Blacklist: Invalidates tokens on logout.
    • Password Hashing: PBKDF2 with SHA256.
    • Strict Role Check: Middleware/Permissions verify Role + Organization Status on every request.
