    Workflow Scenarios & Edge Cases

    1. User Management Workflow

    Hierarchy

    1. Super Admin -> onboards Tenant Admin (Organization created automatically).
    2. Tenant Admin -> creates Normal User (linked to the same Organization).

    Account Lifecycle

    • Invitation: Users can be invited via email tokens.
    • Verification: New users must verify their email (is_email_verified=True) to access full features.
    • Restoration: Soft-deleted users can be Restored by Tenant Admins using the /users/{id}/restore/ endpoint, recovering their access and associations.
    • Hard Deletion: A scheduled Celery task permanently removes users who have been soft-deleted for > 30 days (configurable).

    2. Task Management Workflow

    A. Creation & Assignment

    • Tenant Admin: Can create tasks and assign them to any active user in the Org.
    • Normal User: Can create tasks but MUST be the assignee (Self-Assignment only).

    B. Subtasks

    • Nesting Limit: Max depth is 1. (Parent -> Subtask).
    • Ownership Rule: Users can only create subtasks for parents they OWN.
    • Admin Rule: Tenant Admins can create subtasks for any task in their Org.

    C. Updates

    • Status Change: Updating status to COMPLETED is BLOCKED if the task has active (incomplete) Subtasks. All subtasks must be completed first.
    • Deleted Tasks: Updating a soft-deleted task is BLOCKED for everyone (returns 404/403).

    D. Deletion

    • Parent/Subtask Constraint: You CANNOT delete a Parent Task if it has active Subtasks. You must delete the subtasks first.
    • Effects: Searching for the task returns 404 for Normal Users. Admins can look it up by ID (Read-Only).

    3. Organization Deactivation Workflow

    If an Organization is marked is_active=False (e.g., for non-payment or policy violation):

    1. Login Block:
      • Tenant Admins attempting login receive: "Your organization is deactivated please contact super admin to reactive the organization".
      • Normal Users attempting login receive: "Your organization is deactivated".
    2. Admin Freeze:
      • Super Admins cannot create new Tenant Admins for this Org.
      • Super Admins cannot delete existing Tenant Admins for this Org.
    3. Reactivation:
      • Super Admin patches is_active=True. Access is instantly restored.

    4. Comment Management Utils

    • Create: Users can comment on any task they can view (Own/Assigned).
    • View: Visibility matches Task visibility.
    • Update/Delete: Users can only edit/delete their own comments. Tenant Admins can delete any comment (moderation).

    5. Edge Cases & Constraints

    1. Unique Titles: Task titles must be unique per User constraints (normalized case-insensitive check).
    2. Past Deadlines: Creating/Updating a task with a deadline in the past is blocked.
    3. Self-Assignment: Normal Users trying to assign tasks to colleagues will face a Validation Error.
    4. Deleted Entity Interaction:
      • You cannot assign a task to a deleted user.
      • You cannot create a subtask under a deleted parent.
